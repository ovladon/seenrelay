Use SeenRelay only around a repeated source-backed validation that is materially more expensive than a SeenRelay preflight. Keep the original validation in shadow mode first. Bind one deterministic fact to the existing validator with protectValidation (JavaScript/TypeScript) or protect_validation (Python). For each later revalidation, pass the value already known. Measure SAME_OBSERVED rate, validation cost/latency and SeenRelay overhead. Enable bounded reuse only if the measured economics are positive and caller policy accepts the fact class and freshness window. On UNKNOWN, STALE, CONTESTED, relay failure, or policy rejection, continue the existing validation. OBSERVE only values independently obtained from the source. SeenRelay supplies freshness evidence, not truth.
